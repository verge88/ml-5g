# Калиброванный контроль очереди и диагностических проб

Продолжение первой серии: слабая гауссовская модель давала неприемлемое число
ложных тревог. Старый успешный относительный критерий не означал полезного
детектора. Новый план `protocol.json` проверяет абсолютную ошибку и обнаружение
на новых данных, сохраняя отрицательные результаты первой серии.

Это синтетический опыт. Нативные сообщения 5G, подписи, независимые корни
доверия, обязательная стоимость КИЕ и внешние сетевые воздействия отсутствуют.
Положительный результат не докажет эффективность промышленной системы.

Два фиксированных бустинга различают четыре управляемых механизма. Пассивная
модель получает только уже завершённые пользовательские наблюдения, прошлые
счётчики и известную конфигурацию собственных проб. Полная получает ещё
результат выбранной пробы при допустимом возрасте исходного запроса. Старый
задержавшийся ответ не обновляет возраст и не заменяет более новое наблюдение.
Будущие ответы и истинная очередь не доступны выбору проб.

Решение об опросе использует отдельную замороженную логистическую модель,
обученную на других seeds. Порог тревоги не меняет расписание. Это позволяет
сравнить калибровки на одинаковых наблюдениях без обратной зависимости выбора
порогов и собираемых данных. Не заявляется оптимальность информационного выбора.

Обучение детектора охватывает разные цены и расписания. По здоровым
калибровочным траекториям строятся два порога: наивный 99% квантиль объединённых
записей и 95% квантиль максимумов целых развёртываний с поправкой конечной
выборки. Во втором случае единица обменности — независимое здоровое
развёртывание, а не такт. Для фиксированной ячейки нагрузки/цены/режима/политики
применяется порядковая статистика ceil((n+1)*.95). При строгом превышении и
обменности калибровочных и нового здорового развёртывания вероятность хотя бы
одной тревоги за 280 тактов не выше .05, маргинально по обеим выборкам.

Это применение известного split-conformal принципа, не новая теорема.
Условная гарантия для уже фиксированной калибровки, нового режима нагрузки,
произвольного дрейфа или бесконечной эксплуатации не заявляется. Порог на
записях не имеет такой гарантии для целого развёртывания. Источники:

- Angelopoulos and Bates, https://arxiv.org/abs/2107.07511;
- Oliveira et al., JMLR 2024, https://jmlr.org/papers/v25/23-1553.html.

Основной тест: 120 новых seeds, высокая нагрузка .92, цена .60, общая очередь,
полная модель и калибровка по максимумам. Для ограниченной рисковой политики
нужны одновременно: верхняя односторонняя 95% граница вероятности ложной
тревоги ≤.10 у обеих политик, нижняя граница обнаружения эпизода за 30 тактов
≥.60, нижняя граница разности обнаружения >−.05, верхняя граница изменения
пользовательской p95 <−.10, свежесть дополнительного запроса ≥.80.

Пассивная база, периодическая и случайная политики, одинаковый ограничитель
при периодическом опросе и изолированная очередь — обязательные контроли.
Дополнительный здоровый всплеск .70→.97 проверяет границу обменности, но не
включается в подтверждающее сравнение. Старые тестовые seeds не используются.

Запускать `python -m unittest probe_calibrated.test_study -v`. GitHub Actions
`.github/workflows/calibrated-probe-study.yml` разделяет обучение, сбор здоровой
калибровки, фиксацию порогов и тест. Зафиксированные результаты не изменяются
при неуспехе какого-либо критерия.
