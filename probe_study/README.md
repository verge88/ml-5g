# Причинное влияние контрольных проб на наблюдаемую очередь

Проверяется ограниченная гипотеза: около насыщения общей очереди уменьшение
дополнительной работы проб может улучшить задержку пользователей, однако
сохранение диагностического качества требует отдельной проверки. Это вычислительный
тест на синтетической FCFS-очереди, а не реализация 5G, КИЕ или атаки.

План, параметры, первичное сравнение и совместный критерий успеха зафиксированы
в `protocol.json` до первой основной серии GitHub Actions. Один замороженный
гауссовский классификатор различает четыре управляемых механизма по задержкам:
штатное состояние, дополнительная задержка пути, ожидание приложения и сочетание.
Разметка механизма не является разметкой злонамеренности.

В общей очереди пробы расходуют тот же ресурс, что и рабочие запросы. В изолированной
очереди эффект на пользователей отсутствует по построению. Контроль `ghost`
наблюдает очередь без расходования её ресурса; это идеализированная
невмешивающаяся модель, а не фактически реализованный сетевой режим и не точная
реплика прежнего повторного расчёта по трассам. Пробы возвращаются только после
завершения, устаревшие значения исключаются. Решение использует только доступные
к этому моменту значения. Для каждого исходного seed сохраняются одни и те же
потоки рабочих запросов и требования к обслуживанию при всех политиках.

Сравниваются пассивная база, периодический и случайный опрос, выбор по
неуверенности классификатора, а также периодическая и рисковая политики с
ограничителем по прошедшему потоку запросов. Это эвристика риска, не точное
вычисление ожидаемой информации. Все политики получают одинаковые счётчики;
ограничитель использует оценку свободной номинальной мощности, а не истинное
состояние очереди или название механизма. Максимальный бюджет одинаков, фактически
использованное число проб может различаться и публикуется.

Обучение использует seeds 101–120, отдельная описательная калибровка 501–510,
тест 2001–2060. Настройки не выбираются по калибровке. В основном эксперименте
60 независимых seeds и 25920 трасс; несколько трасс одного seed не считаются
независимыми повторениями. Парные интервалы строятся по seed-кластерам.
Подтверждающее сравнение одно; остальные срезы служат поиском контрпримеров.

Совместный успех: в заранее выбранном срезе load=.92, work=.60, shared
верхняя граница 95% интервала относительной разности пользовательской p95 меньше
−10%, а нижняя граница интервала разности macro-F1 больше −.03.
Неуспех любого условия запрещает вывод о совместном улучшении.
Предельная загрузка, работа, задержки и время являются абстрактными единицами,
не миллисекундами Open5GS. Доля ложных тревог оценивается, но не ограничивается
теоремой. Стоимость обязательного КИЕ, криптографии, байты и аппаратная нагрузка
не моделируются. Новизна и производственная применимость не установлены.

Воспроизводимость: Python 3.12, numpy 2.2.6.

```
python -m unittest probe_study.test_study -v
python -m probe_study.study --stage fit --output frozen
python -m probe_study.study --stage evaluate --models frozen --output out
```

GitHub Actions: `.github/workflows/probe-observer-study.yml` — отдельное обучение,
три независимых задания оценки по 20 seeds и сборка отчёта. Артефакты содержат
замороженные параметры, хеши плана/модели, исходные результаты каждой трассы,
парные интервалы, отрицательные результаты и сведения о среде.
