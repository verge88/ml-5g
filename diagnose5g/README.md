# Диагностический пилот после анализа литературы

Первый шаг нового метода: проверить различимость двух управляемых механизмов при наличии дополнительного измерительного пути. Это не окончательная проверка нового алгоритма и не доказательство преимущества ML.

План зафиксирован в plan.json до основной серии. Новые Open5GS2.7.6: обучение1301–1303, калибровка1304, тест1305–1306. Четыре семейства по два эпизода: штатный режим, задержка пользовательского тракта, ожидание внутри независимого приложения, сочетание двух изменений. Каждый эпизод40 наблюдений;18 разогревочных на развёртывание. Все воздействия ограничены собственным закрытым Docker-стендом. Настройки воздействия известны только сборщику/оценщику.

Измеряются два пути к одному подписывающему приложению: UE–UPF–приложение и обход пользовательского тракта со стороны ядра. Квитанции подписываются одним гостевым Ed25519-ключом, привязанным к последовательному журналу гостя. Два пути не объявляются независимыми свидетелями безопасности. Исходные КЦ AUSF/NSSF и свидетель процесса сохранены. Управление ожиданием приложения доступно только через127.0.0.1 ядра. Гипервизор, физический хост и часы сборщика доверенные.

В признаки допускаются только две измеренные медианы. Названия эпизодов, номера развёртываний, время команды и величины задержки исключены. Штатные и изменённые эпизоды оцениваются на одинаковых заранее заданных позициях22–39. Это классификация известного управляемого механизма; не метка атаки. Измеренное изменение услуги публикуется для каждого эпизода, включая слабый/неудачный эффект.

Первичное сравнение: одна фиксированная гауссовская диагностическая модель с конечным измерением и с двумя измерениями. Дополнительно — логистическая регрессия и усиление деревьев на обоих составах признаков. Вклад нового наблюдения не отождествляется с преимуществом обучения. До теста замораживаются модели и калибровочный порог отказа от решения; два тестовых развёртывания не дают основания для значимости или эксплуатационных гарантий.

Прототип расписания сравнивается на тех же сырых журналах: фиксированная периодичность, обновление по возрасту и выбор по ожидаемому снижению ошибки. Не более10 дополнительных двухпробных партий на40точек. Ответ невыбранной пробы недоступен алгоритму. Устаревшее значение не считается текущим, отказавшая проба не обновляет возраст. После исчерпания бюджета потеря свежести явно отражается. Обязательный КЦ выполняется одинаково для всех политик вне этого дополнительного бюджета; его стоимость нельзя скрывать при будущем полном сравнении.

Все пробы в данной серии физически собираются. Уменьшение запросов в повторном расчёте — условная оценка; уменьшение фактического процессорного времени или нагрузки на услугу здесь не измеряется. Модель старения и условная независимость измерений внутри класса являются приближениями. Контроль ошибок при дрейфе и модель общих доменов доверия ещё не реализованы. Это ограничения пилота, а не доказанные свойства полного предлагаемого метода.

Проверки:

* tests/test_diagnose5g.py: отсутствие будущих/невыбранных данных, запрет признаков актуатора, бюджет, старение, неуспешные пробы, границы воздействий;
* diagnose5g.audit: подписи, соответствие запросам, медианы из сырых проб, наличие UE-нонсов в захвате трафика, отдельный гостевой идентификатор загрузки, подписи исходного КЦ;
* отдельные задания fit/evaluate: тестовые артефакты не скачиваются в обучение, контроль хешей и списков исходных развёртываний.

Workflow: .github/workflows/diagnose5g.yml. Старый прогнозный эксперимент не изменяется.
